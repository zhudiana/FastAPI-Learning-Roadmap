# Data Validation & Serialization (Pydantic)

FastAPI uses **Pydantic** for data validation, serialization, and type safety.

Instead of manually checking every incoming request, you define **Python classes (models)** that describe the structure of your data. FastAPI automatically validates requests against these models.

Pydantic is built into FastAPI and works as the bridge between:

- Client JSON data
- Python objects
- API responses

---

## Why Pydantic?

Without Pydantic, you would manually check:

- Does the user send all required fields?
- Are the fields the correct type?
- Is the email actually an email?
- Are values within allowed ranges?

With Pydantic, FastAPI handles this automatically.

---

# 1. Creating a Pydantic Model

Pydantic models inherit from `BaseModel`.

Example:

```python
from pydantic import BaseModel


class User(BaseModel):
    name: str
    age: int
    email: str
```

This model describes the expected structure:

```json
{
  "name": "John",
  "age": 25,
  "email": "john@example.com"
}
```

FastAPI now knows:

- `name` must be a string
- `age` must be an integer
- `email` must be a string

---

# 2. Input Validation

When a request comes into FastAPI, it checks the JSON body against the Pydantic model.

Example:

```python
from fastapi import FastAPI
from pydantic import BaseModel


app = FastAPI()


class User(BaseModel):
    name: str
    age: int


@app.post("/users")
def create_user(user: User):
    return user
```

## Valid Request

Request:

```json
{
  "name": "Alice",
  "age": 22
}
```

Response:

```json
{
  "name": "Alice",
  "age": 22
}
```

---

## Invalid Request

Request:

```json
{
  "name": "Alice",
  "age": "twenty"
}
```

FastAPI rejects it automatically:

```json
{
  "detail": [
    {
      "type": "int_parsing",
      "loc": ["body", "age"],
      "msg": "Input should be a valid integer"
    }
  ]
}
```

No extra validation code is needed.

---

# 3. Automatic Type Conversion

Pydantic can also convert compatible types.

Example:

Model:

```python
class Product(BaseModel):
    name: str
    price: float
```

Incoming JSON:

```json
{
  "name": "Laptop",
  "price": "999.99"
}
```

Pydantic converts:

```python
price = 999.99
```

because the string can be converted into a float.

---

# 4. Required vs Optional Fields

By default, fields are required.

Example:

```python
class User(BaseModel):
    username: str
    age: int
```

This requires:

```json
{
  "username": "alex",
  "age": 20
}
```

Missing `age` causes an error.

---

Optional field:

```python
from typing import Optional


class User(BaseModel):
    username: str
    age: Optional[int] = None
```

Now this is valid:

```json
{
  "username": "alex"
}
```

---

# 5. Data Validation Rules

Pydantic allows extra validation rules.

Example:

```python
from pydantic import BaseModel, Field


class Product(BaseModel):
    name: str
    price: float = Field(gt=0)
```

`gt=0` means:

- price must be greater than 0

Invalid:

```json
{
  "name": "Phone",
  "price": -10
}
```

FastAPI returns an error.

---

# 6. Output Serialization

Serialization means converting Python objects into JSON responses.

Example:

```python
class User(BaseModel):
    id: int
    username: str


@app.get("/users/1", response_model=User)
def get_user():
    return {
        "id": 1,
        "username": "alex",
        "password_hash": "abc123"
    }
```

The database might return:

```json
{
  "id": 1,
  "username": "alex",
  "password_hash": "abc123"
}
```

But FastAPI uses the response model:

```python
response_model=User
```

and sends:

```json
{
  "id": 1,
  "username": "alex"
}
```

The sensitive field is removed automatically.

---

# 7. Separating Database Models and API Models

A common pattern is creating different models.

Example:

Database object:

```python
class UserDB(BaseModel):
    id: int
    username: str
    password_hash: str
```

API response model:

```python
class UserResponse(BaseModel):
    id: int
    username: str
```

Endpoint:

```python
@app.get(
    "/users/{id}",
    response_model=UserResponse
)
def get_user(id: int):
    return user_from_database
```

The API never exposes `password_hash`.

---

# 8. Documentation Synchronization

Pydantic models automatically update FastAPI documentation.

Example:

```python
class User(BaseModel):
    name: str
    age: int


@app.post("/users")
def create_user(user: User):
    return user
```

FastAPI automatically generates:

- Request body schema
- Required fields
- Field types
- Example structure

in Swagger UI.

Access:

```
http://localhost:8000/docs
```

The documentation always matches your code.

---

# Summary

Pydantic provides:

| Feature          | Purpose                                |
| ---------------- | -------------------------------------- |
| Input Validation | Checks incoming request data           |
| Type Safety      | Ensures correct Python types           |
| Automatic Errors | Returns detailed validation errors     |
| Serialization    | Converts Python objects to JSON        |
| Field Filtering  | Removes unwanted fields from responses |
| Documentation    | Keeps Swagger UI synchronized          |

---

## Key Idea

FastAPI + Pydantic means:

**Define the data structure once → validation, conversion, serialization, and documentation happen automatically.**
